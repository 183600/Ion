# Ion Codebase Bug Fix List

## Identified Bugs and Fixes

### 1. Cookie Eviction Bug (FIXED)
- **File**: `src/cookies.mbt`, `src/cookie_bug_wbtest.mbt`
- **Issue**: The `cookie_evict_for_capacity` function was using `cookie.creation != oldest.creation` as the filter condition to remove evicted cookies. When a cookie is replaced, it preserves the original creation timestamp, so multiple cookies can have the same creation value. The filter would incorrectly remove ALL cookies with that creation value instead of just the one being evicted.
- **Fix**: Changed the filter to use `!cookie_same_identity(cookie, oldest)` which compares name, domain, path, host_only, and bracketed identity. This ensures only the specific cookie being evicted is removed.
- **Commit**: `d06198e` - "fix: cookie eviction uses identity instead of creation timestamp"
- **Test**: `cookie_bug_wbtest.mbt` - two tests verify the fix

### 2. Cookie Path Default Bug (FIXED)
- **File**: `src/cookies.mbt`
- **Issue**: The `cookie_path_matches` function did not handle empty cookie paths correctly. Per RFC 6265 §5.1.4, an empty cookie-path should default to "/".
- **Fix**: Added handling for empty paths by setting `effective_path = "/" when cookie_path.length() == 0`, and using `effective_path` for all subsequent comparisons.
- **Commit**: `96c74ff` - "cookies: treat empty cookie-path as default-path-per-RFC-6265"

### 3. DNS Header Bug (FIXED)
- **File**: `src/dns.mbt`
- **Issue**: The DNS response parser was missing the ARCOUNT byte in the 12-byte header. The second ARCOUNT byte was not being written, causing the question section to start one byte early, which would make conforming servers read ARCOUNT from the question's first length byte and fail to parse the shifted question.
- **Fix**: Added `header.write_byte(0)` to write the ARCOUNT byte (set to 0 for queries with no additional records).
- **Commit**: `a4ec26c` - "dns: fix truncated query header, tolerate unknown RR types, add tests"
